## Design Studio (2026-11-16)
The Cover Generator page has two modes: **Generate with AI** (the original flow) and **Design Studio**.
- Code: `src/components/coverStudio/CoverStudio.js` (editor) and `src/components/coverStudio/backgrounds.js` (flat procedural templates, palettes, grain). Uses `fabric` v7.
- The canvas backing store is always 1800x900 and is scaled with CSS only, so the export is exactly what is on screen. Do not change the canvas size.
- Logos load from `/api/cover-generator/logo-preview/:symbol` with `crossOrigin="anonymous"`. Anything drawn on the canvas must be CORS-enabled or the export is blocked.
- Use gradients and paths only in `backgrounds.js` (no `ctx.filter`, Safari does not support it).
- **Grain is never resized.** Fine (single-pixel) grain is the default the owner wants, and it only stays pattern-free when shown pixel for pixel; resizing it creates a woven ripple (moire). So the editor is three stacked layers inside `Stage`: `BgLayer` (1800x900 background, CSS-scaled, no grain), `GrainLayer` (one grain field at exactly the screen's device pixels, strength = CSS opacity), then the transparent fabric canvas (logos, text, watermark). The downloaded file is composed separately in `exportDataUrl()` with grain drawn at 1800x900. Do not put grain back into a CSS-scaled canvas. "Coarser grain" is the soft blurred variant. Thumbnails always use the soft variant.
- **Shift keeps a dragged item on the line it started on** (owner 2026-11-19). In the `object:moving` handler: with Shift held, the item's `top` (or `left`) is put back to `e.transform.original`, whichever way the pointer has moved less, so it can be pressed at any point of the drag and switches between across and up/down as the pointer moves. It works with Option+drag too, so the copy lands in line with the original. The line it is held on is drawn through the item's middle.
- **Items snap to each other, not only to the cover** (owner 2026-11-19). Same handler: besides the cover's centre lines and safe margins (pink guide), the dragged item's left / centre / right and top / middle / bottom snap to the same lines of every other item (blue guide, `guides.vi` / `guides.hi`). The other items' boxes are worked out once per drag (`others`, keyed by `e.transform`). Left out: the items being moved, what travels with them (name, title, bar), label bars and seals. The nearest line within 6 screen pixels wins. A copy being pulled off also snaps to where it came from. A multi-selection snaps by its whole box. Cmd still bypasses snapping, the Snap tick box switches both kinds off.
- **Groups** (owner 2026-11-19: "select 2 or more items and group them", so they align and snap as one). A group is only a shared id, `studio.gid`, on its items; they stay ordinary items (no fabric Group, so history, drafts, layouts and painting are unchanged). `groupSelected` / `ungroupSelected` (toolbar Group / Ungroup, the multi-selection Edit panel, Cmd/Ctrl+G and Shift+Cmd/Ctrl+G). A name, title or caption belongs to its owner, so the owner joins the group. **A click on one member selects them all**: the `mouse:down:before` handler makes an `ActiveSelection` of the members and then calls fabric's private `_cacheTransformEventData(e)` so fabric looks again and starts the drag on the selection (checked against fabric 7.4.0; if a later fabric drops that method, a click selects only the one item). Shift+click and Cmd/Ctrl+click are left alone (Cmd/Ctrl+click picks one item), and so is an item already selected on its own. **Double-click a member** to select it alone (a text goes into typing); the Layers list also picks single items. Because a selected group is an ActiveSelection, dragging it snaps its whole box to the cover and to other items. `alignSelected` counts a group as one piece (`alignCount` too), and `alignTo` ("Place on cover") now also works for several selected items as one block. Copies: `duplicate` drops the id from a single copied item; Option+drag gives the copies a new id of their own (`<old>-<stamp>`) and drops it from a copy that ended up alone.
- **Snapping must call `o.setCoords()` before measuring.** fabric moves the object to the pointer, fires `object:moving`, and only then refreshes its cached corners. Reading `getBoundingRect()` without refreshing gives the previous step's position, which made dragged logos stutter and lurch near every guide. Snapping can be turned off (Snap checkbox) or bypassed with Cmd (Option/Alt now drags a copy).
- **Government seals** (their own "Seals" tab in the left panel; the owner could not find them as a switch inside Logos) come from `GET /api/cover-generator/seals` (only `grounded` entries with an `imageUrl`). A seal is a logo item with `studio.seal = true`: it starts large, at 22% opacity, sent to the back, and is skipped by the auto layouts. Seals are full-colour discs, so the single-tone modes use `monoEmblem()` (luminance to alpha) instead of a flat tint; always repaint items through `paintItem()`.
- **The owner uses Safari.** Fixed-ratio thumbnails use the `Thumb` padding-bottom box, never `aspect-ratio` on an image inside a scrolling grid (Safari collapses those rows into strips). Scrolling grids set `grid-auto-rows: max-content`. Check new UI in real Safari (`safaridriver`), and tell the owner before opening an automation window: touching it shows a "remotely controlled" prompt.
- Template house rules (owner feedback 2026-11-16): dark fields only, never white or light backgrounds. No hard colour blocks, panels, diagonal splits, overlapping discs or light beams. Soft glows, fine line work and grain are what the owner wants.
- The owner also removed Flow Lines, Guilloche, Halo and Veils, and the blue (Midnight Navy, Cobalt), green (Deep Teal, Forest), red (Oxblood), orange (Ember) and yellow (Amber Ink) palettes. Do not bring those back. A new cover starts on the owner's own colours (`DEFAULT_PALETTE`, id `signal`, "Violet and Aqua"): base black `#000000`, accent purple `#6a4cf5`, second aqua `#00fdb1` (set 2026-11-16, replacing Royal Violet as the default).
- **Contrast** (Background, Finish) is `applyContrast()` in `backgrounds.js`: an S-curve around the picture's own average brightness, applied to pixels (no `ctx.filter`) before the vignettes and grain, so it is in the export too. It pivots on the average because covers are dark; a mid-grey pivot would only darken them. Inputs are dithered by a fraction of a level so stretched gradients do not band. A newly loaded image resets it to 0.
- **Adding a text never resizes a logo** (owner 2026-11-19; Design Studio). The automatic centred layout (`applyLayout('center', true)`) gives logos less height once there is text, so adding a headline used to shrink the logo. `addText` now places the new text itself when there is a logo and the layout is the centred one (or automatic layout is off because something was moved by hand): centred under the logos, below any text already stacked there, the text box narrowed if the logo is near an edge so nothing leaves the cover, and no lower than the watermark line. The logos are not touched. With no logo, or with the "left" or "bottom" one-click layouts, the layout runs as before (those do not change logo size when text arrives). Adding another LOGO still re-runs the layout and may resize logos to fit side by side: that is the one case the owner wants.
- **Size and position** (Background tab, both studios) are `bg.zoom`, `bg.shiftX` and `bg.shiftY`, applied inside `renderBackground()` to the image or the template, so the live view and the export always agree. Shifts are a share of the cover's width and height. Whatever the picture no longer reaches is filled with the palette's base colour. The background is its own layer and is never selectable; keep it that way, the owner asked for sliders so it cannot be picked up by accident. "Centre on the open area" (`openArea()` / `centreBackground()` in `CoverStudio.js`) finds solid panels or stacks of framed photos against an edge, moves the middle of the background to the middle of what is left, and enlarges it only as far as needed to keep every edge covered. A new image keeps the position.
- In the AI backdrop tab, "Use my colours below instead of the style defaults" is ticked by default (owner 2026-11-16).
- **Black backdrops** (owner 2026-11-23: more AI backdrop styles, all on a black base). The style list from the server now carries `backdropOnly` and `pending`. The AI backdrop tab shows `backdropOnly && !pending` styles first, under "Black backdrops", then the Cover Generator's own styles under "Cover generator styles" (that second label only appears when there is a first group). These styles are `internal`, so the Cover Generator page never lists them. Their base is always black on the server; "Use my colours" only changes their two accent colours. Which ones exist and which are still waiting for approval is decided in the backend (see its CLAUDE.md).
- **Studio fonts** are listed in `FONTS` (CoverStudio.js) and loaded in `studioFonts.js`. Families with `italic: true` get an Italic checkbox. Montserrat (all nine weights), Instrument Serif and Bebas Neue (one weight, capitals only, SIL Open Font License, added 2026-11-18) come from `@fontsource`. Added the same day, also from `@fontsource` (all SIL Open Font License): Geist (the package's family name is `Geist Sans`; the list shows it as "Geist" through the entry's `label`), Geist Mono, Plus Jakarta Sans and DM Sans. **Instrument Serif starts in italic when it is picked from the list** (owner 2026-11-18; `italicFirst` on its `FONTS` entry, applied in `pickFont` and the hover preview; the Italic tick box switches it off). **Instrument Serif is the only serif in the list** (owner 2026-11-18: Playfair Display, Source Serif 4, Newsreader, Fraunces and DM Serif Display were removed, packages included; do not add serifs back unasked). **Orbitron Extra bold** (one weight, `@fontsource/orbitron`, SIL Open Font License, under "Display") was added on 2026-11-19: the owner sent a screenshot set in HK Modular Bold (paid, Hanken Design Co.), asked for the closest FREE font, and chose Orbitron Extra bold from Orbitron, Audiowide and Tektur. Only that weight was asked for. **Satoshi was asked for and NOT added:** Fontshare's ITF Free Font License v2.0 (17 Aug 2026, read 2026-11-18 at fontshare.com/licenses/itf-ffl) allows self-hosting for the licensee's own site but section 02 forbids making the font "available as a selectable font for third-party users" in a design tool or template editor, and forbids handing it to contractors. The same applies to every Fontshare closed-source font. A person can still download it from Fontshare themselves and add it under "Your own fonts". CMG Sans (a renamed Montserrat derivative, SIL Open Font License) is not on npm: its files are in `coverStudio/fonts/cmg-sans/` as latin subsets, with its special cuts (Wide, Wide Outline, Outline) exposed as separate families under "Display". The Rounded, Slab, Backslant and Mono Digits cuts were removed on 2026-11-18 at the owner's request (list entries, CSS and files). **Only publish fonts whose licence allows it:** the bundle is public, so any font added here is downloadable by anyone. On 2026-11-16 the owner also asked for Styrene A, Aeonik, Pilat Wide, HK Modular and Roc Grotesk; those are commercial and were NOT added (the copies on this Mac are trial files or have no known web licence). Add them only once the owner supplies licensed web-font files. Until then they are used through **"Your own fonts"** (Text tab, `userFonts.js`): the person adds font files from their own computer, the browser registers them with the FontFace API and remembers them in IndexedDB (`cg_studio_fonts`). Those files are never uploaded or bundled, so nothing commercial is published. Family, weight and italic are read from the file's own `name` and `OS/2` tables (file name as a fallback for woff/woff2).
- No emojis and no em dashes in UI copy.

## Interview Cover Studio (2026-11-16)
The third mode tab on the Cover Generator page. It is the same editor component (`CoverStudio.js`) mounted with `profile="interview"`, so the two never share a canvas or state, but they share the engine. Building blocks live in `coverStudio/interviewKit.js`.
- **Size is 1920x1080** (owner's call; article covers stay 1800x900). Inside the component use `W` / `H`, never `COVER_W` / `COVER_H`. `renderBackground()` takes `designW` / `designH`.
- **Guest photo** = one image object (`studio.kind === 'photo'`) whose picture is drawn by `paintPhoto()`: photo inside a circle, rectangle or polygon mask, optional rounded corners, the mask can be turned without turning the photo, zoom and pan inside the mask, colour / black and white / gradient map, its own colour edits, colour behind a cut-out, border. Change settings through `setPhoto()` (it repaints and re-lays-out).
- **Name, title, label bar, and the ECOSYSTEM caption are ordinary objects that follow a parent** (`studio.attach = { to, role, rel, dx, dy }`). `layoutAttached(frame)` places them: the name is the larger line, and both are scaled down so they are never wider than the mask before they wrap. Hand edits (dragging a name, changing its size) are kept as offsets. Anything that moves or resizes a parent must call `layoutAttached`. **A guest sizes as one piece** (owner 2026-11-16: no scaling each part on its own): corner-dragging the photo, the "Whole guest" slider (shown for the photo and for its name or title), selecting the parts together and scaling the group, and "Size of every guest at once" in the Guests tab all go through the same layout. `takeHandEdits` tells a group move or group scale (the text rode along with its photo) apart from a real hand edit; without that check the text was scaled twice. The label bar is not selectable: it is redrawn under its photo, live during a group drag (`liveBarsRef`).
- **Name strip** (owner 2026-11-17): under the toolbar, one cell per guest that has a name plate, in reading order, with Name and Title fields and left / centre / right buttons (plus "Align all"). Clicking into a field selects that guest on the cover. Typing in a field (the strip or the Edit panel, both go through `setGuestTextOf`) applies the owner's rules: the line returns to the layout's size (`ATTACH_REL`: name 0.105, title 0.06 of the photo's width), which is its largest, and is made smaller only as far as needed to fit the plate's inner width; the title is also kept below the name's size. A line sized by hand on the cover is marked `attach.free` and is then left at whatever the person made it (even wider than the photo) until it is typed in a field again. An empty line takes no room, so a guest with no title gets a shorter plate.
- Switching a guest's text style to None stores the name and title (text, font, colour, size, offsets) in `studio.kept` and brings them back when the style is switched on again. Do not go back to recreating the "Guest Name" placeholders; the owner lost typed names that way.
- **Changing layout keeps the person's work** (owner 2026-11-17). `applyInterviewLayout` first runs `harvest()`: typed headline, subtitle, pill, "Brought to you by" and ECOSYSTEM text, the two slot logos, every guest's photo, name and title (reading order), and grain on the colour panel go into `carryRef`. The new layout is then built and filled with them, in the new layout's own positions and style. Content only: fonts, sizes and colours come from the new layout. A line counts as typed when it differs from `studio.seed` (the placeholder it was made with). Carried text is fitted into the room the layout's placeholder takes (`fitTo` in `makeText`). Layouts that show names in capitals keep the typed form in `studio.raw`. Anything the new layout has no place for (a third guest, a subtitle) stays in `carryRef` and returns with a layout that has one. Items made by a layout carry `studio.tpl`; items the person added themselves (extra text, shapes, logos) are left where they are, but guests always move into the new layout's guest places. "Start again with empty placeholders" in the Layouts tab clears the carry.
- **Photo background erase** (`photoCutout.js`, button in a guest's Edit panel; owner chose the free in-browser route on 2026-11-17). MODNet portrait model (`models/modnet.onnx`, 26 MB, Apache 2.0, from Hugging Face `Xenova/modnet` at commit fa2fa54, sha256 07c308cf...84df9) run with `onnxruntime-web` 1.16.3 (MIT, pinned exactly) as single-threaded WebAssembly. Keep it worker-free and thread-free: the live policy has no `blob:` workers and no cross-origin isolation. It is a people model: it does not work on logos or on pictures that are already cropped into a circle on a flat colour.

An adjustment is plain data, `{ darken, contrast, hue, sat, light, bands: { red: [h, s, l], ... }, map: [colours] }`, and like a gradient it is never changed in place. It lives on `studio.adjust` of an image item (`kind: 'logo'`, applied in `paintItem`, only while the item's colour is Original) and of a guest photo (applied in `treated()` in interviewKit.js, before the photo look), and on `bg.adjust` for a background IMAGE (applied in `renderBackground`, before Darken and Contrast; a new image resets it). `bands` are the eight colour families (`BANDS`: reds, oranges, yellows, greens, aquas, blues, purples, magentas): each has its own hue, saturation and lightness, weighted by how near a pixel's hue is to the family, and greys are left alone. All done on pixels (no `ctx.filter`). **Two passes:** while a slider moves, `setAdjustQuick(true)` makes `adjustedPicture()` work on a small copy (560 px), and 240 ms after it rests `restAdjust` redoes it properly (up to 2400 px); `exportDataUrl` finishes any pending pass first. `adjustedPicture` may return a canvas SMALLER than the original (same shape), so callers draw it at the size they want (`tintedCanvas` takes the width and height). The panel piece is `AdjustControls`, opened by an "Edit image" / "Edit photo" / "Edit this image" button (Edit panel of an image, Photo section of a guest, Background > Image). `photoSig` and the history check for logos include `adjustKey`, so Undo repaints.
- **Blur and tilt shift** (owner 2026-11-19, in the same edit tools; `imageAdjust.js`). `adjust.blur` (0..1) puts the whole picture out of focus; `adjust.tilt` = `{ amount, shape: 'band' | 'circle', x, y, size, feather, angle }` keeps one area sharp and blurs the rest (Off / Band / Circle in `AdjustControls`, with sliders for the blur, where the sharp area is, its size, how soft its edge is, and the band's angle). No `ctx.filter`: the blur is three box blurs on pixels (`blurPixels`, colours weighted by alpha so see-through edges do not bleed), worked out on a small copy (at most 1100 px, smaller for strong blurs) and stretched back. Tilt shift lays two blurred copies (a lighter one nearer the sharp area) over the picture through gradient masks (`fadeIn`, `destination-in`). Strength is a share of the picture's longer side (`BLUR_REACH`), so the quick pass and the full pass look the same. Order in `adjustedPicture`: colours, then focus, then the gradient map.
- **Gradient map replaced Tint** (owner 2026-11-19: "instead of tint I would like to have a gradient map ... up to 5 colours, one side representing blacks and the other representing whites"). Two to five colours (`MAP_MIN` / `MAP_MAX`), evenly spaced from blacks to whites; each pixel takes the colour its brightness points at (`mapPixels`). A guest photo's look is now Colour / Black and white / Gradient map: `studio.treatment === 'map'` with `studio.mapColors`. **Covers saved with the old Tint still draw the same**: `photoMap()` reads `treatment: 'tint'` as the two-colour map black to `tintColor` (which is exactly what the tint did), and the first edit turns it into a real map. Images and backgrounds get the same map as `adjust.map` (Off / On in `AdjustControls`). Changing the number of colours keeps both ends and reads the ones between off the current ramp (`resizeMap`). `MapControls` is the panel piece.
- **Frames have two background removals, and pick the right one by themselves** (owner 2026-11-19: a logo put into a guest frame lost most of itself to "Remove the background", which is the people model). A frame's Edit panel now has "Remove the background" (people, `cutOutPhoto`) and "Remove plain background" (a flat single colour, `cutOutPhotoPlain`, the same `removePlainBackground` logos use, without trimming). The control once called "Colour behind a cut-out photo" is now **"Background colour of the frame"** (same settings, `backdrop` / `backdropGrad`). Choosing a colour there, or putting a picture into a frame that already has one, goes through `clearBehind`, which looks at the picture's outer edge (`edgeKind` in interviewKit.js): already see-through means nothing is removed, one flat colour all the way round (at least 94% of the edge, stricter than the button's 75% so a portrait against a plain wall still counts as a photo) means the plain removal, anything else the people cut-out. An empty mask (a shape made into one) shows the background colour when one is set.
- **Colour behind a cut-out photo also removes the background** (owner 2026-11-19: "almost as a short cut to select a color and remove background in a single step"). `setPhoto` runs `cutOutPhoto` when a colour or gradient is chosen and the photo has not been cut out yet; a photo put into a frame that already has one is cut out too (`placeGuestPhoto`). `cutBusyRef` stops a second run while one is going (a colour box fires many changes while it is dragged). None clears the colour and leaves the cut-out as it is.
- **Font picker** (`FontPicker`): a custom list, not a native select, because the owner wants the selected text to preview a font on hover and native options report no hover. `previewFont` sets the font without touching the history and puts the real one back when the pointer leaves or the list closes; `pickFont` commits through `setFont`.
- **Grain on one shape** (`studio.grain` on a shape, slider in its Edit panel). Drawn only where the shape is seen: its outline minus everything stacked above it (`paintShapeGrain`). On screen it is its own layer at screen pixels above the fabric canvas, redrawn after each canvas render; in the file it is drawn at cover pixels into the overlay. Never draw it inside the fabric canvas while editing: that canvas is resized by CSS and fine grain would ripple. Items above the shape are drawn to a separate sheet and cut out with `destination-out`, because fabric resets the blend mode for every object it renders.
- The border has a "Same border on every guest photo" tick box (`ringAll`, `setRing`): ticking it copies the selected guest's border to all, and later border changes go to every guest while it is ticked.
- **Patterns** (owner 2026-11-19, from three reference covers; `patterns.js`, the "Patterns" tab in both studios). Three kinds, listed in `PATTERNS`: `plus` (fine lines with a plus where they cross), `grid` (plain squares) and `tiles` (rounded tiles with a thin ground between them). **A pattern is a shape item** (`StudioRect`, `studio.kind === 'shape'`) with `studio.pattern = { type, size, ratio, weight, plus, lines, gap, round, offX, offY }`, drawn in `StudioRect._renderFill` in place of the fill. So layering, opacity, history, drafts, duplicating and rounded corners all come from shapes; nothing new had to be added to `buildItem`. Its colour is the shape's `fill`, its strength the shape's opacity. One square is drawn once on a small sheet and repeated with `createPattern` (kept per item in a WeakMap), so tiny squares cost nothing; sizes are whole cover pixels so the repeats meet without seams. It is drawn in cover pixels whatever the item's stretch (`ctx.scale(1 / scaleX, 1 / scaleY)`), so resizing the item shows more or less pattern and never stretches it. `ratio` (-1..1) turns the squares into tall or wide rectangles, up to four to one, for all three kinds. `studio.pattern` is replaced on every edit, never changed in place. A new pattern covers the whole cover, goes to the back, and is **locked**. To show it over a panel, the owner drags it above the panel in Layers.
- **Locked items** (`studio.locked`, `applyLock`): not selectable, not evented and without handles, so clicks on the cover go through to what is underneath. Made for patterns (a full-cover item would otherwise catch every click). A locked item is selected from the Layers list or the Patterns tab; its Edit panel has the "Locked in place" tick box. `applyLock` runs wherever an item is made or its settings are swapped: `addPattern`, `buildItem`, `cloneItem`, history `restore`. Only patterns have the tick box so far. Patterns are also left out of snapping.
- **Picture overlays**: the Patterns tab has "Add a PNG from my computer" (the same file input as the Logos tab, so the PNG becomes an ordinary image item). There is no built-in overlay library yet: the owner has not supplied files.
- **Agilera was asked for and NOT added to the font list** (2026-11-19). It is a commercial font (Asenbayu Type Foundry; the file's own copyright line reads "All Rights Reserved"; sold on MyFonts and Fontspring). The copy on this Mac is a desktop download, not a web-font licence, and the bundle is public. Same rule as Styrene, Aeonik and HK Modular: it is used through "Your own fonts" (Text tab), which keeps the file in the person's browser and then lists the font in the drop-down for them. Add it to `FONTS` only when the owner has a licence that allows hosting it for other people to use in a design tool.
- **Space Grotesk has all five of its weights** (Light 300 to Bold 700; Light and Semibold added 2026-11-23 when the owner asked for the font of the clawpump.tech wordmark, which is Space Grotesk Bold, lower case, letter spacing -25).
- **The interview studio has ten tabs, five to a row** (`Tab` with `$quarter`: `flex: 0 0 20%`, slightly smaller text). An eleventh needs a new plan.
- **Text along a shape's outline** (owner 2026-11-19: "type on a shape path for the outside or inside"; `ringText.js`). It is a setting of the shape, `studio.ring = { text, side: 'out' | 'in', flip, start, gap, size, spacing, family, weight, italic, color, only }`, drawn by `StudioRect._render` after the shape, so it moves, resizes, rounds, turns, copies, undoes and saves with the shape and needed no new kind of item. It is typed in the shape's Edit panel ("Text along the outline"), not on the cover. The letters stand on the shape's rounded-rectangle outline moved out or in (`outline()` walks it clockwise from the middle of the top edge; moving it outward rounds the corners by the same amount), one letter at a time, each turned to the outline. `flip` makes it read along the bottom (tops toward the middle, running the other way); `start` moves it round, with 0 the natural reading place for either. `only` hides the shape and shows just the words. Drawn in cover pixels whatever the shape's stretch, like patterns. Its font is loaded in `setShapeText` and, for a draft, in `loadCover` (which now also collects ring fonts). A ring object is replaced on every edit. **Several lines** (owner 2026-11-19: Enter for another line): the box is a text area, and each line is a ring of its own, one line's height (`leading`, a share of the letter size) farther out or in than the one before, stacked the way they are read (where the text reads normally, the first line is the upper one on the cover). One text per shape: for one text along the top and another along the bottom, duplicate the shape and hide the copy's shape. **No overlap and no odd gaps** (owner 2026-11-19: a long line ran over its own beginning; then, after a first fix that wrapped it, "no weird gaps"). `ring.fit` is `'auto'` unless the "Close the ring" tick box is off (`'centre'`). In `'auto'`, all in `paintRing`: (1) a typed line up to `OVER` (1.45) times too long for its ring stays on that one ring; (2) a much longer line is shared between rings word by word (`wrap`) and then evened out, each typed line on its own (the least fill that still fits it into the same number of rings), so there is no full ring followed by a short leftover; (3) every ring that fills at least `CLOSE_FROM` (60%) of its path, and every ring that shares a typed line, is **closed**: its letters are spread evenly all the way round (or, when too long, drawn smaller by the same factor, `ctx.scale` per letter), with a word space where the last word meets the first. A shorter line stays as typed, centred on its place. How many rings there are decides how large each is (outside text reading along the top puts the first line outermost), so the count is settled by trying the smallest number that holds everything (`snug` handles the case where one ring more would leave the last one empty). `'centre'` keeps typed spacing: long lines wrap and leave their gaps, and one very long word is drawn tighter. **Letters with their own look** (owner 2026-11-19: single characters must be able to take their own colour, font and size): `ring.marks = { [place in the text]: { size, family, weight, italic, color } }`. The person highlights letters in the text box; the box's selection is kept in `ringSel` / `ringSelRef` (read on select, key up and mouse up, because the highlight is no longer visible once a slider is clicked, so a note under the box names what is highlighted, with a "Whole text" button). While letters are highlighted, Letter size, Font, weight, italic and colour go to those letters only (`styleRing` with a range); spacing, distance, position and the rest always apply to the whole text. Typing keeps each look on its own letters (`retextRing` re-indexes the marks around what changed; typed letters take the look of the one before). `ringFaces` lists every font a ring uses, for loading. **The shape and its text scale together** (same request): a corner drag (an even stretch, `evenStretch`) scales the letters and their distance from the outline with the shape, live while dragging and on release (`scaleRing` in the `object:modified` handler); the toolbar's Size does the same. A side drag, or the Width and Height sliders, only reshape the shape and leave the letters their size. Not offered for guest photos, label bars or patterns.
- **A shape can become a mask for an image** (owner 2026-11-19: "a button that makes it a mask ... like our guest masks"). `makeMask` (button "Make it a mask" in a shape's Edit panel) swaps the shape for a picture frame, the same kind of item a guest photo is (`studio.kind === 'photo'`), with the shape's outline (circle, or rectangle with the same proportion and rounding), place, size, turn, opacity, layer and group. It has `studio.mask = true`, no name or title (`textStyle: 'none'`) and `studio.maskFill` (the shape's colour, shown with a small picture sign while it is empty, drawn in `paintPhoto`). An image dropped on it, or chosen in its Edit panel, is cropped to the shape and gets every photo tool (zoom, move, border, colour edits, background removal). **A mask is not a guest**: everywhere that used `!studio.host` to mean "a guest" now also checks `!studio.mask` (layout changes leave it in place, "Size of every guest at once" skips it, it is listed as "Mask"). The shape's outline text, gradient, grain and pattern are not carried over; Undo brings the shape back. Shapes taller than about 3.3 to 1 are limited by the photo mask's own range (`aspect` no lower than 0.3).
- **Part of a text in its own size or colour** (owner 2026-11-19: "highlight any portion of the text and change its size or color"). While a text is being typed in on the cover (double-click) and letters are highlighted, the Size slider and the Colour controls call `styleText`, which uses fabric's `setSelectionStyles` on that range only; with nothing highlighted they change the whole text as before. fabric keeps the per-letter values in the text's `styles`. Clicking in the side panel does not end the typing or lose the highlight (fabric's `blur` only stops the cursor blinking), which is what makes this work. `capture` now stores `styles` (through `copyStyles`, so history never shares them with the live text) and `restore` puts them back; drafts keep them because they are part of the stored props. When the whole text changes size (the slider, or dragging a corner), letters with a size of their own are scaled by the same factor (`scaleLetterSizes`); a whole-text colour change leaves coloured letters as they are. "Make every letter the same again" clears them. The panel follows the highlight through `text:selection:changed`. Not for the outline text of a shape or the name strip fields, which have one style each.
- **Shapes** are fabric `Rect`s (`studio.kind === 'shape'`, `studio.round` 0..1). **Text boxes** (the Interview pill, highlight bars) are `studio.box` on a text object, drawn by an instance override in `applyTextBox()` with caching off.
- **Layouts** (`INTERVIEW_LAYOUTS`) are data: applying one clears the cover and creates ordinary objects (placeholder guests, placeholder logos, text, panels). Placeholder logos (`studio.placeholder`) are filled by clicking a library logo or uploading while one is selected. A selected logo's Edit panel also carries the logo library (search + grid) and a file button, both of which swap the logo in place (`replaceLogo`). **Hidden file inputs must sit outside the tab panels**: the logo input used to live inside the Logos tab, so the Edit tab's file button had nothing to click and did nothing.
- **Logos**: "Remove plain background" (`removePlainBackground`) works inwards from the edges and only on a single flat colour. It is not a photo cut-out tool.
- The Genfinity wordmark for the "Brought to you by" line is `genfinity-wordmark-white.png` (supplied by the owner).
